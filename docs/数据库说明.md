## 2. 连接配置

系统里有三套数据库入口，全部指向同一个 MySQL 实例。

### 2.1 Laravel 主连接（薪酬、考勤、组织、开票、维保等）

- 配置链：`.env` 的 `DB_*` → `config/database.php` 的 `mysql` 连接。
- 生产实测：

```dotenv
DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_DATABASE=payroll
DB_USERNAME=payroll
DB_PASSWORD=[REDACTED]
```

### 2.2 采购模块独立 PDO

- 代码：`app/Purchase/Support.php::db()`；配置：`config/procurement.php`。
- 配置链：`.env` 的 `PROC_DB_HOST/PORT/NAME/USER/PASS`，缺省回落到 `DB_*` 的值或 `payroll`。
- 生产实测：

```dotenv
PROC_DB_HOST=127.0.0.1
PROC_DB_PORT=3306
PROC_DB_NAME=payroll
PROC_DB_USER=payroll
PROC_DB_PASS=[REDACTED]
```

- 约束：`PROC_DB_NAME` 必须与 `DB_DATABASE` 相同，否则视为「合并未生效」；`deploy/merge-procurement-db.sh` 会直接拒绝执行。
- 代码中的 `payroll.payroll_projects`、`payroll.payroll_accounts`、`payroll.app_messages` 是限定名，当前库即 `payroll`，与实际表名等价；保留限定名不影响运行。

### 2.3 财务模块独立 PDO

- 代码：`app/Finance/Support.php::fdb()`；配置：`config/finance.php`。
- 配置链：`.env` 的 `FINANCE_DB_DATABASE` + `DB_HOST/PORT/USERNAME/PASSWORD`。
- 生产实测 `FINANCE_DB_DATABASE=payroll`，即财务也读写主库。
- ⚠️ `app/Finance/Support.php` 的 `pass` 参数存在硬编码兜底值，属于历史遗留安全问题；后续应改为必须显式配置，本次未改动。

### 2.4 库归属速查

| 模块 | 连接方式 | 生产目标库 |
|---|---|---|
| 薪酬/考勤/人员/组织/报表/开票/维保 | Laravel `DB_*` | `payroll` |
| 采购 | 独立 PDO `PROC_DB_*` | `payroll` |
| 财务 | 独立 PDO `FINANCE_DB_DATABASE` | `payroll`（可临时切 `gy_finance` 回滚） |

## 4. 采购 12 表字段与索引

### 4.1 products（标准商品库）

| 字段 | 类型 | 允许空 | 默认 | 键 |
|---|---|---|---|---|
| id | int | 否 | — | PRI |
| line | varchar(20) | 否 | — | MUL（`uk_line_name_spec`） |
| category | varchar(50) | 否 | — | 同上 |
| name | varchar(100) | 否 | — | 同上 |
| brand | varchar(50) | 是 | NULL | 同上 |
| spec | varchar(100) | 是 | NULL | 同上 |
| unit | varchar(20) | 是 | NULL | — |
| status | tinyint | 是 | 1 | — |
| created_at | datetime | 是 | CURRENT_TIMESTAMP | — |

唯一键 `uk_line_name_spec(line,category,name,brand,spec)`，用于归入时防重复。

### 4.2 product_synonyms（商品别名）

`id`(PRI)、`product_id`(MUL)、`alias`(UNI)。`alias` 全局唯一。

### 4.3 purchase_items（月度填报明细）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | int | 主键 |
| month | char(7) | `YYYY-MM`，索引 `(month,project_id)`、`(month,line)` |
| project_id | int | 关联 `payroll_projects.id` |
| line | varchar(20) | 条线 |
| product_id | int | 标准商品 id，清单外为 NULL |
| item_name / brand / spec / unit | varchar | 填报内容 |
| quantity | decimal(10,2) | 数量，默认 0 |
| stock | decimal(10,2) | 库存 |
| reason / use_location / remark | varchar | 用途/地点/备注 |
| is_custom | tinyint | 是否清单外 |
| custom_reviewed | tinyint | **主库新增列**：清单外是否已审核 |
| status | enum | `draft/submitted/confirmed/returned` |
| price | decimal(10,2) | 单价 |
| return_reason / returned_at / resubmitted_at | — | 退回轨迹 |
| created_by / created_at / updated_at | — | 审计字段 |

### 4.4 archived_purchases（归档采购事实表）

`id`、`month`、`project_id`、`item_id`（2026-11-21 新增，关联 `purchase_items.id`，删除退回填报时按此精确删存档；历史行迁移时按字段一对一回填，匹配不到为 NULL）、`line`、`product_id`、`item_name`、`brand`、`spec`、`unit`、`quantity`、`price`、`total`、`remark`、`created_at`。
索引：`month`、`project_id`、`line`、`item_id`。汇总、预算执行、驾驶舱均只读此表。

### 4.5 budget_plan（项目月度预算）

`id`、`month`、`project_id`、`amount`、`updated_by`、`updated_at`；唯一键 `uk_month_proj(month,project_id)`。

### 4.6 fill_windows（填报窗口）

`id`、`month`(UNI)、`start_date`、`end_date`、`status`、`created_at`。

### 4.7 monthly_archive（月度归档锁）

`month`(PRI)、`archived_at`、`archived_by`、`note`。有记录即该月锁定。

### 4.8 op_logs（采购操作日志）

`id`、`user_id`、`username`、`role`、`action`(MUL)、`detail`、`created_at`(MUL)。

### 4.9 audit_records（清单外归入审计）

`id`、`item_id`、`product_id`、`action enum(map/new/ignore)`、`alias_saved`、`note`、`created_by`、`created_at`。

### 4.10 notifications（采购站内通知）

`id`、`user_id`(MUL)、`type`、`title`、`content`、`is_read`、`created_at`；索引 `(user_id,is_read)`。同时镜像写平台 `app_messages`。

### 4.11 sys_settings（采购设置）

`skey`(PRI)、`svalue`、`updated_at`。常用键：`price_threshold`（价格异常环比阈值，默认 30）。

### 4.12 projects（采购展示用项目表）

`id`、`code`(UNI)、`name`、`manager`、`phone`、`sort_no`、`status`、`created_at`。
由 `PurchaseController::syncProjectsThrottled()` 每 5 分钟从 `org_nodes(type=project)` 同步一次；业务外键一律使用 `payroll_projects.id`，本表只作兼容/展示。

```bash

bash deploy/merge-procurement-db.sh
# 可覆盖参数：
# LEGACY_DB=gy_procurement APP_DIR=/var/www/payroll/laravel-app bash deploy/merge-procurement-db.sh
```

行为：

| 场景 | 行为 |
|---|---|
| `PROC_DB_NAME != DB_DATABASE` | 直接失败，提示合并没有生效 |
| 旧库存在 | 仅主库缺表才 `CREATE TABLE ... LIKE`；按列交集 `INSERT IGNORE ... SELECT` 补差；再逐表按主键核对缺失数、比对金额合计 |
| 旧库不存在 | 跳过补差，退化为纯核验，输出主库行数并通过 |
| 旧库有主库没有的列 | 拒绝写入并报错，避免丢列 |

## 6. 回滚办法

### 6.1 本次改动是否需要回滚

- 代码：本次没有改 PHP 业务代码，仅新增脚本与文档；回滚只需还原 `changelog.json`/文档，业务无感。
- 数据：没有执行任何删除、覆盖，主库数据未变；因此**不需要数据回滚**。
- 旧库：`gy_procurement` 已于 2026-11-20 备份后 DROP，不可直接查询；需要时按 6.3 从 dump 重建副本。

### 6.2 数据库回滚（如后续有人误操作）

```bash
# 1) 查看快照
ls -lh /root/pre_proc_merge_20261120_145443/

# 2) 恢复整个实例中的 payroll（谨慎：会覆盖当前库）
gunzip < /root/pre_proc_merge_20261120_145443/db.sql.gz | mysql -uroot -p
# 或只恢复单库：
# zcat db.sql.gz | sed -n '/CREATE DATABASE.*`payroll`/,/CREATE DATABASE.*`gy_procurement`/p' | mysql -uroot -p

# 3) 代码回滚
tar -xzf /root/pre_proc_merge_20261120_145443/code.tar.gz -C /var/www/payroll/laravel-app
```

## 8. 运维红线与排障

1. **不要把 `PROC_DB_NAME` / `FINANCE_DB_DATABASE` 指回旧库**。旧库结构落后，回切会导致列缺失与数据回退。
2. **不要给采购表加 `payroll_` 前缀**，也不要重命名薪酬表；代码与历史数据都按现名硬编码。
3. **跨库限定名是冗余但安全**的：`payroll.xxx` 当前就是本库；如未来改库名，再统一去掉限定名。
4. `information_schema.tables.table_rows` 是估算值；核验行数一律用 `COUNT(*)`。
5. 手工执行 `mysqldump` 加 `--no-tablespaces`，避免 payroll 用户缺 PROCESS 权限产生告警。
6. 任何 DDL/DROP 前先 `mysqldump` 并 `gzip -t` 校验；生产变更必须留快照路径与 md5。
