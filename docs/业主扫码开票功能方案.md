> 版本：v0.4（2026-11-16）｜ 状态：**方案定稿，待开发**，未开发、未改任何源码、未触碰生产数据

**实现层保留能力（不是业务承诺，不需再决策）**

- 数据模型允许同一账套被多个项目绑定（`invoice_project_bindings` 不对 `account_set_id` 做唯一约束）；业务默认且只承诺「一项目一账套」。若未来需要多项目复用，无需改表，仅调整配置与统计口径。
- 同理，一个项目如需拆分多个账套（按楼栋/业务线）不在本期承诺范围；若发生，扫码入口需增加账套参数。

> 仍有少量业务口径未定，见 §12；不影响本次定稿的结构与隔离设计。

## 0. 术语约定

| 术语 | 定义 | 状态 |
|---|---|---|
| **账套** | 开票数据与权限的最小隔离单元。一套账套包含：①开票主体（营业执照名称、统一社会信用代码/税号、地址电话、开户行与账号）；②该主体对应的诺诺凭据（appKey/appSecret、多主体授权标识、环境）；③审核人名单；④商品编码与税率；⑤交付邮箱配置 | ✅ 概念已确认 |
| **开票主体** | 数电票上的销方，营业执照口径；一个账套内唯一 | ✅ 已确认 |
| **项目** | 业务归属（小区/管理处），业主扫码入口挂在项目上 | ✅ 已确认 |
| **项目 ↔ 账套** | 每个项目有且只有一个账套；扫码后按项目解析出唯一账套，再由账套决定主体与审核人 | ✅ 已确认（1:1） |
| **审核人** | 账套级配置的人员名单，决定「我的审核待办」归属；权限点仍是最终闸门 | ✅ 已确认（不同账套不同审核人） |
| **主审人** | 每个账套指定一名主审人，作为待办默认负责人与超时提醒对象；其他审核人仍可审 | ✅ 已确认（管理员指定） |
| **开票管理员** | 新增角色，`scope=all`，可查看全部账套的申请单、发票、统计，并可配置各账套审核人；不继承系统设置等其他模块权限 | ✅ 已确认 |
| **申请单** | 业主提交的一次开票请求，落 `account_set_id` 快照，提交后不随项目绑定变更而改账套 | ✅ 已确认 |

## 2. 整体业务流程

```
物业在后台配置账套（主体 + 诺诺凭据 + 审核人 + 商品编码税率 + 邮箱）
        │
        └→ 把项目绑定到账套，生成项目级开票二维码
        │
        ▼
业主扫码 → 解析 project → 找到 account_set → 确定开票主体与审核人
        ▼
H5 第 1 屏：填写开票金额 + 抬头（个人/企业）   ← 展示开票主体名称
     第 2 屏：上传缴费凭证（1–3 张，jpg/png/pdf）
     提交
        ▼
申请单落该账套 → 进入该账套审核人「我的待办（按账套分组）」
        │
        ▼
审核人人工核额（凭证金额 vs 申报金额）→ 通过 / 退回（原因）
        │                                   └→ 业主可修改金额/附件后重提
        ▼
审核通过 → 用该账套的诺诺凭据与主体开数电票（异步）
        │                          └→ 失败：可重试自动退避，参数类错误转人工
        ▼
用该账套的邮箱配置交付（PDF/下载链接）→ 已交付
        │
        └→ 红冲（红字确认单）→ 红冲成功 → 如需重开：新申请，关联原单
```

### 2.1 状态机（沿用 v0.2，12 态）

| 状态 | 含义 | 可迁移到 | 触发 |
|---|---|---|---|
| `draft` | 业主已扫码未提交（前端本地态，可不落库） | `submitted` | 提交 |
| `submitted` | 待审核（金额为业主申报值） | `approved` / `rejected` / `cancelled` | 审核 / 业主撤回 |
| `rejected` | 已退回 | `submitted`（version+1）/ `closed` | 业主修改重提 |
| `approved` | 审核通过，金额已核定 | `issuing` | 系统自动/人工发起 |
| `issuing` | 开票中 | `issued` / `failed` | 诺诺回执 |
| `issued` | 已开票 | `delivering` / `red_flushing` | 开票成功 |
| `delivering` | 交付中（邮箱） | `delivered` / `delivered_failed` | 邮件回执 |
| `delivered` | 已交付（终态，可红冲） | `red_flushing` | — |
| `failed` | 开票失败（可重试/待人工） | `issuing` | 重试 |
| `red_flushing` | 红冲中 | `red_flushed` / `red_flush_failed` | 诺诺回执 |
| `red_flushed` | 已红冲（终态） | — | — |
| `cancelled` | 业主撤回 / 后台关闭 | — | — |

规则（含账套相关约束）：
- **审核即锁额**：`approved` 后 `verified_amount` 只读；再改必须退回重审。
- **幂等键**：`project_id + house_no + request_no` 唯一（`request_no` 服务端生成，如 `INV20261116-000123`）；业主重复点击提交由前端禁用 + 后端幂等键拦截。
- **账套快照**：申请单提交时写入 `account_set_id` 与主体/税率/商品编码快照；此后项目改绑账套、账套改主体，均不影响在途单。
- **账套不可跨**：任何状态迁移都校验操作人对该 `account_set_id` 有权限；跨账套一律 `403 ACCOUNT_SET_FORBIDDEN` 并写审计。
- **审核人归属**：仅用于待办分组与提醒；实际能否操作仍由权限点 + 账套范围决定（见 §8）。
- **重复开票防护**：同 `项目 + 房号 + 费项期间 + 金额` 在 30 天内已有活动申请时，提交前置提示并进入人工复核标记（不直接拒绝，避免误伤分次缴费）。
- **退回重提**：在原单上 `version+1`，保留历史版本快照（金额、附件、抬头）。
- **失败处理**：网络/限流/5xx 自动重试（1/5/15 分钟，最多 3 次）；税号/编码/资质类错误不重试，落 `failed` 并标红。
- **红冲**：仅 `issued/delivered` 且未红冲的单；数电票红冲走「红字确认单」，需记录确认单号与红票号码；红冲成功后原单锁定。
- **回调丢失**：`issuing` 超 5 分钟未回执，定时任务主动查询诺诺状态。

### 2.2 账套解析与隔离规则

| 环节 | 规则 |
|---|---|
| 扫码入口 | `GET /invoice/entry?p={projectToken}` → 解析 `project_id` → 查 `invoice_project_bindings` → 得到唯一 `account_set_id`；只返回主体**展示名称**、是否开通、房号规则，不返回凭据、内部 ID |
| 项目绑定 | **一项目一账套**：`project_id` 唯一；同一账套可被多个项目绑定的能力仅在实现层保留，业务不承诺 |
| 项目未绑账套 | 入口直接提示「该项目暂未开通开票」，不允许进入表单（不是提交时才报错） |
| 账套停用 | 与未绑定同样处理；后台保留历史单查询，不再接收新单 |
| 申请单落库 | `account_set_id` 必填；主体名称/税号/税率/商品编码同时写快照字段 |
| 审核人配置 | 由开票管理员（`scope=all` + `invoice_config`）在账套配置页增删审核人、指定主审人；保存即生效，变更写审计 |
| 主审人 | 每账套最多 1 名主审人，作为未处理待办的默认负责人与超时提醒对象；主审人必须同时是审核人 |
| 待办路由 | 按 `account_set_id` + `invoice_account_set_reviewers` 分组；无审核人的账套进入「未分配」分组，仅 `scope=all` 且 `invoice_review` 可见 |
| 开票管理员视图 | 可切换「全部账套」，查看所有账套申请单、发票与统计，并可进入任一账套配置审核人；不因此获得系统设置、薪酬等模块权限 |
| 改绑项目 | 只影响改绑之后的新单；在途单仍按快照账套处理，避免审核人与主体漂移 |
| 统计导出 | 必须先算「可访问账套集合」，SQL 强制 `account_set_id IN (...)`；账套下拉只列可访问项 |
| 跨账套查看 | 即使拿到单号/ID，详情、预览、下载、审核、重开全部 403 并记录 `cross_account_set_denied` 审计 |

## 3. 开票金额来源与校验（主线：业主自填 + 凭证 + 人工核额）

### 3.1 来源定义
- 金额由**业主在 H5 填写**（价税合计），必须上传 **缴费凭证**（物业费收据/转账截图/收费单照片）。
- 系统**不**关联缴款单，也**不**自动带出金额；审核人以凭证为准，人工核定 `verified_amount`。
- 若凭证金额与申报金额不一致：审核人可直接修正核定金额（需填差异原因），或退回让业主重填。

### 3.2 后端校验（硬性）
1. 金额：`> 0`，两位小数，上限按**账套**配置（默认 50,000 元/单；便于不同主体按各自风险设定）。
2. 附件：**必填 1–3 张**；格式 `jpg/jpeg/png/pdf`；单张 ≤ 5MB、合计 ≤ 12MB；服务端校验 MIME 与真实文件头，不信任扩展名。
3. 抬头：企业必须填 15/17/18/20 位统一社会信用代码并通过校验位校验；个人抬头不填税号。
4. 邮箱：必填（唯一交付渠道），格式校验；建议二次确认输入。
5. 房号：必填，格式 `楼栋-单元-房号` 或项目自定义规则（可配置正则）。
6. 账套：按项目映射账套；项目未绑定、账套停用或主体信息不完整时**禁止提交**（入口直接提示）。
7. 重复：同项目+房号已有 `submitted/approved/issuing/issued/delivered` 时，给出"已有开票申请"提示并展示状态查询入口。

### 3.3 合理性提示（软性，标黄不拦截）
- 与**同账套**同房号历史开票金额均值偏差 > 200% → 列表标"金额异常"。
- 单笔 > 账套配置上限的 80% → 标"大额"。
- 同一房号 30 天内第 2 次及以上提交 → 标"重复提交"。
- 审核页对这些标记给出醒目提示，但不阻断流程。

### 3.4 伪造风险与审核要点
- 凭证可被 PS/截图复用：审核时看**收款方名称、金额、日期、房号/业主姓名**四要素是否与申报一致，并核对是否与历史凭证重复（可按文件 md5 查重，命中提示"疑似重复凭证"）。
- 附件存**私有目录**，不提供公开直链；后台预览走带权限的临时签名 URL。
- 业主端展示合规提示："请上传真实缴费凭证，虚假材料将移交处理"。
- 所有提交记录保留 IP、UA、时间，便于追溯。

## 4. 数据表设计（新增，`invoice_` 前缀）

> 落地原则：**全部新建表**，不改 `payroll_*`、`fin_*`；`project` 的账套归属用映射表表达（逻辑上等价于 `project.account_set_id`），避免动被薪酬等模块共用的 `payroll_projects`。

### 4.1 `invoice_account_sets`（账套，v0.3 取代 v0.2 的 `invoice_subjects`）

## 7. 诺诺数电票对接要点

### 7.1 鉴权（按账套）
- 每个账套独立 `appKey + appSecret`，换 `access_token`；缓存 key 为 `nuonuo:token:{account_set_code}:{env}`，提前 5 分钟刷新，换 token 加锁，账套之间不共用 token。
- 密钥存储见 §4.1：appKey 明文、appSecret 加密入库；列表/接口只回显掩码；沙箱与正式环境隔离（`nuonuo_env`）。
- 多主体授权标识 `nuonuo_org_id` 与账套绑定；调用前校验主体授权状态，未授权直接拦截并提示「账套未授权」。

### 7.2 开票请求字段映射（数电票，字段名以诺诺正式文档为准）
| 本地 | 诺诺（示意） | 说明 |
|---|---|---|
| `{account_set_code}-{request_no}` | `orderNo` | 幂等键，带账套前缀防跨账套撞号；重复请求返回同一结果 |
| seller_name_snapshot / seller_tax_no_snapshot | `sellerName` / `sellerTaxNo` | 来自申请单快照，不用实时主数据 |
| title / buyer_tax_no | `buyerName` / `buyerTaxNo` | 个人可空 |
| verified_amount | `totalAmount` | 价税合计 |
| tax_amount / amount_ex_tax | `taxAmount` / `amountWithoutTax` | 服务端反算并校验 |
| 商品行 | `items[]`：`goodsName`、`goodsCode`、`taxRate`、`quantity`、`price` | 取自账套配置与申请单快照 |
| 发票类型 | `invoiceType` | 数电普票（专票需资质） |
| 邮箱 | `email` | 默认不用诺诺代发：回传 PDF 由本站 SMTP 发送；`email_provider=nuonuo` 时才走代交付 |
| 备注 | `remark` | 可写费项期间 |

### 7.3 税率与商品编码
- 按**账套**配置 `default_goods_code + default_tax_rate`（物业费通常 6%，需财务确认）；同一主体下不同费项需要多编码时，后续可扩展 `invoice_account_set_goods` 子表（P2）。
- 税率变更只影响新申请，历史单按开票时快照（`tax_rate_snapshot`）。
- 商品编码错误会导致开票失败且多为不可重试，上线前需在沙箱按账套逐一验证。

### 7.4 交付与下载时效（v0.4 定稿）
- 开票成功后诺诺返回 PDF/OFD/XML 地址（有效期有限），**必须落库并转存**到本站私有存储，避免链接过期。
- **默认交付：本站自建 SMTP 发送**。发件人取账套 `email_from`，附件用转存后的 PDF（可选同时附 OFD），正文含发票号码、金额、销方与查询入口。
- **诺诺代发为可选开关**：账套 `email_provider=nuonuo` 时才走诺诺代交付；上线前须先向诺诺确认是否收费，若收费则保持 `smtp`。
- **SMTP 配置粒度（推荐）**：全局默认 + 账套级覆盖。全局配置放 `.env`（`MAIL_*`）供所有账套复用；账套可单独配置发件邮箱与授权码（`smtp_*` 字段，密码加密存储），用于不同主体需要不同发件域名的场景。推荐先用全局一套，出现发件域名/退信隔离需求再按账套覆盖。
- **发送失败处理**：同步失败立即记 `invoice_delivery_logs`；自动重试 3 次（1/5/15 分钟），仍失败则状态标 `delivered_failed` 并告警（站内待办 + 邮件/日志），支持人工「重发」；页面下载始终可用，不阻塞业主领票。
- 页面下载：签名 URL，业主凭查询密钥获取，不暴露内部 ID 与账套内部信息。

### 7.5 红冲
- 数电票红冲按**账套**发起：红字确认单 → 购方确认 → 开具红票；不同账套不能互相红冲。
- 需记录 `red_confirm_no`、`red_invoice_no`、红冲原因；红冲中禁止重复发起；失败可重试或转人工。

### 7.6 失败码处理（分类）
| 类型 | 示例 | 处理 |
|---|---|---|
| 网络/超时/限流 | 连接失败、429、5xx | 自动重试，指数退避 |
| 参数错误 | 税号格式、抬头与税号不匹配、商品编码非法 | 不重试，退回业主/管理员修正 |
| 资质/额度 | 账套未授权、销方未绑定、额度不足、账号欠费 | 不重试，后台告警到账套负责人 |
| 凭据错误 | appKey/appSecret 失效、token 获取失败 | 不重试，账套配置页标红并提示「测试连接」 |
| 幂等冲突 | 单号已存在且状态不同 | 主动查询对齐，不重复开票 |

## 8. 角色、权限、账套范围与审计（v0.4 定稿）

### 8.1 角色定义

| 角色 | role_key | scope | 权限点 | 可见范围 | 可配置审核人 |
|---|---|---|---|---|---|
| 系统管理员 | `admin` | all | `*` | 全部 | 可 |
| **开票管理员** | `invoice_admin`（预置角色） | all | `invoice_view / invoice_review / invoice_issue / invoice_stats / invoice_config` | **全部账套**的申请单、发票、统计（停用账套只读） | **可**（仅允许配置账套审核人，不涉及其它模块） |
| 账套审核人 | 按账号现有 `role` | account_set | `invoice_view / invoice_review`（按需 `invoice_issue`） | 仅 `invoice_account_set_reviewers` 绑定的账套 | 否 |
| 项目财务 / 客服 | 按账号现有 `role` | project | `invoice_view / invoice_review`（按需 `invoice_stats`） | 仅所属项目绑定的账套 | 否 |

- 「开票管理员」是开票模块内的管理角色，**不等于系统管理员**：不继承薪酬、系统设置等其它模块权限，也不能查看 appSecret 明文。
- 新账号默认 `scope=project`；需要 `account_set` 或 `all` 时由系统管理员显式调整，避免默认放大。
- 审核人名单不授予权限：名单内账号若无 `invoice_review`，仍不可审核。

### 8.2 权限点（加在 `AppModules::tree()` 的 `finance` 节点）
| 权限点 | 名称 | 说明 |
|---|---|---|
| `invoice_view` | 开票申请查看 | 列表/详情/导出 |
| `invoice_review` | 开票审核 | 核定金额、通过、退回 |
| `invoice_issue` | 开票与红冲 | 发起、重试、红冲、重开、重发 |
| `invoice_stats` | 开票统计 | 统计页与导出 |
| `invoice_config` | 账套与审核人配置 | 账套 CRUD、凭据、审核人（含主审）、项目绑定 |

### 8.3 账套级范围与判定
沿用 `scope` 字段：`all` / `account_set` / `project`。

| scope | 可见账套集合 | 默认值/说明 |
|---|---|---|
| `all` | 全部账套（停用账套只读） | 系统管理员、**开票管理员** |
| `account_set` | 仅 `invoice_account_set_reviewers` 中绑定且 `enabled=1` 的账套 | 新增账号不默认此项 |
| `project` | 仅 `payroll_accounts.project_name` 对应项目绑定的账套 | **新增账号默认** |
| 未识别/空 | 按 `project` 处理（最小权限） | 兜底 |

**判定顺序（后端 `InvoiceGuard` 统一实现）**：
1. `admin` 或 `permissions` 含 `*` → 放行（配置类操作仍要求 `invoice_config`）；
2. 校验权限点（`invoice_view/review/issue/stats/config`）；
3. 计算可访问账套集合 `accessibleAccountSets(account)`；
4. 计算可访问项目集合（`scope=project` 时锁定 `project_name`）；
5. 目标单据的 `account_set_id` 必须 ∈ 可访问账套集合，否则 `403 ACCOUNT_SET_FORBIDDEN`；
6. 统计/导出/列表一律追加 `account_set_id IN (...)`，不允许前端传任意账套 ID。

**默认与边界**：
- 新建账套未分配审核人：仅 `scope=all` + `invoice_review` 能在「未分配」分组看到，并在页面顶部提示；**不自动回退给项目账号**。
- 主审人只影响待办归属与提醒，不影响其他审核人的审核权。
- 审核人增删、主审变更**保存即生效**；变更记录操作人、前后名单与时间。
- `scope=project` 账号的账套下拉只显示本项目绑定的账套，项目筛选锁定。
- 统计页可切换「按账套 / 按项目」，但两者都在可访问集合内。

### 8.4 越权拒绝规则

| 场景 | 结果 |
|---|---|
| 无对应权限点调用接口 | `403 PERMISSION_DENIED` |
| `scope=project/account_set` 访问未授权账套的单据、凭证、发票 | `403 ACCOUNT_SET_FORBIDDEN` + `cross_account_set_denied` 审计 |
| 非 `invoice_config` 调用账套/审核人配置接口 | `403 PERMISSION_DENIED`（前端隐藏按钮不作为安全边界） |
| 项目账号把自己加入审核人或提升自己的 scope | 拒绝；仅系统管理员可调整账号 scope，开票管理员仅可配置账套审核人 |
| 查看/导出 appSecret | 任何角色均不可；接口只返回掩码与「已配置」 |
| 对停用账套发起新开票 | 拒绝；历史单据仍可按权限只读 |

### 8.5 审计
- `invoice_request_logs` 全量状态变更，带 `account_set_id`。
- 审核/红冲/账套配置/审核人变更额外写 `op_logs`；凭据变更只记录「已轮换 + 操作人 + 时间 + 结果」，不记录明文。
- 敏感信息（税号/邮箱/手机）列表脱敏；凭据永不回传前端。

## 9. 配置项（按账套）

| 配置 | 位置 | 说明 |
|---|---|---|
| 账套主体信息（名称/税号/地址电话/银行） | `invoice_account_sets` | 每账套独立 |
| 项目 ↔ 账套 | `invoice_project_bindings` | **一项目一账套**；同账套多项目复用仅为技术能力 |
| 账套审核人与主审人 | `invoice_account_set_reviewers` | 开票管理员界面配置，保存即生效 |
| 商品编码、税率、单笔上限 | `invoice_account_sets` | 按账套；开票时快照 |
| 诺诺 appKey/appSecret/orgId/环境 | `invoice_account_sets`（secret 加密） | 账套间不共用；`NUONUO_SECRET_OVERRIDE_{CODE}` 可覆盖；轮换保留 24h 回滚窗口 |
| 交付方式 | 全局 `.env` + `invoice_account_sets.email_provider` | 默认 `smtp`；`nuonuo` 为可选开关（先确认是否收费） |
| SMTP 配置 | 全局 `.env`（`MAIL_*`）+ 账套 `smtp_*` 覆盖 | 推荐全局一套，按发件域名/退信隔离需求再按账套覆盖；密码加密 |
| 邮件重试与告警 | 配置项 + `invoice_delivery_logs` | 3 次（1/5/15 分钟），失败标 `delivered_failed` 并告警 |
| 房号正则、凭证数量与大小 | 配置项（按项目或账套覆盖） | 默认 1–3 张 / 5MB / 12MB |
| 自动重试次数、回调超时 | 配置项 | 默认 3 次 / 5 分钟 |

## 10. 异常与人工兜底

| 异常 | 处理 |
|---|---|
| 凭证造假/重复使用 | md5 查重提示、四要素人工核对、留痕可追溯 |
| 申报金额与凭证不符 | 审核改额并填差异原因，或退回重填 |
| 重复提交 | 幂等键 + 同房号近期活动单提示；不硬拒绝分次缴费 |
| 项目未绑账套 / 账套停用 | 入口即拦截，提示「暂未开通」；后台保留历史查询 |
| 账套未分配审核人 | 进入「未分配」分组，仅 `scope=all` 可见并告警 |
| 跨账套访问/代审 | 403 + `cross_account_set_denied` 审计 |
| 凭据失效/未授权 | 账套配置页标红，「测试连接」给出失败码；不自动重试 |
| 凭据轮换失败 | 新 secret 测试不通过则不切换；已切换的可在 24h 回滚窗口内一键回退旧 secret |
| 诺诺超时/5xx | 自动重试 + 主动查询补偿 |
| 回调丢失/重复 | 幂等 + 定时轮询（按账套取 token） |
| 参数类失败 | 不重试，标红转人工 |
| 邮件发送失败 | 自动重试 3 次（1/5/15 分钟）；仍失败标 `delivered_failed` 并告警，支持人工重发；页面下载始终可用 |
| SMTP 授权码失效/发件域名异常 | 发送日志记录错误码，告警到开票管理员；修正账套 SMTP 覆盖或全局配置后可重发 |
| 发票已开需作废 | 只走红冲，不允许直接改数 |

## 11. 分期排期与工作量估算

> 估算为开发+自测人力（不含诺诺资质审批、电子税务局授权、邮件通道采购等待时间）；1 人日 ≈ 1 个工作日。

| 阶段 | 范围 | 估算 |
|---|---|---|
| **P0 / MVP** | 账套 CRUD 与项目绑定、凭据加密存储/环境变量覆盖/轮换与「测试连接」、开票管理员角色、审核人（含主审）配置与账套级隔离；项目入口与二维码；H5 三屏（填金额抬头/传凭证/看进度）；附件私有存储与预览；后台审核页（核定金额、通过、退回）；数电票开票（按账套取 token、幂等与重试）；邮箱交付（默认本站 SMTP，诺诺代发开关预留）；状态查询与 PDF 下载；审计；基础权限点 | **约 14–18 人日** |
| P1 | 红冲与重开、回调+轮询补偿、失败分类与自动重试策略细化、发票查询统计页（账套/项目双维度 + 明细 + 导出）、软标记（金额异常/重复凭证）、我的审核待办分组优化 | **约 6–8 人日** |
| P2 | 专票支持、短信通知、批量审核/批量开票、凭证 OCR 辅助核额、同一主体多商品编码（按费项） | **约 6–9 人日** |

**MVP 拆分参考**

| 模块 | 估算 |
|---|---|
| 账套 + 项目绑定 + 审核人 + 账套级隔离 | 3 人日 |
| H5 三屏 + 附件上传 | 4 人日 |
| 后台审核页（含凭证预览） | 2.5 人日 |
| 诺诺开票 + 邮箱交付 + 状态/下载 | 3.5 人日 |
| 审计、权限点、测试与联调 | 2–4 人日 |

**MVP 边界（明确不做）**
- 不做红冲/重开（先人工走诺诺后台处理，系统保留入口占位）
- 不做统计报表页（先导出/人工汇总；数据字段已预留）
- 不做短信、不做 OCR、不做专票
- 不做与收费系统对账
- 不做同一账套多商品编码（P2）

**前置依赖**：诺诺开放平台账号与多主体授权、每个账套的营业执照与税号、电子税务局数字账户与代理授权、商品编码与税率确认、邮箱通道（SMTP 或诺诺代发）、H5 域名与 HTTPS（已有）。详见 `docs/诺诺与电子税务局配置清单.md`。

## 12. 决策清单（v0.4 定稿）

**已确认（不再讨论）**
1. ✅ 金额来源：业主自填 + 凭证附件 + 人工核额（无缴费记录）。
2. ✅ 开票类型：数电票；诺诺账号与资质已就绪。
3. ✅ 一项目一账套：每个项目有且只有一个开票账套，账套对应各自营业执照与税号。
4. ✅ 交付渠道：先只做邮箱；默认本站自建 SMTP，诺诺代发为可选开关（需先确认是否收费）。
5. ✅ 不对账，但需按项目/账套看开票量、金额、状态分布与明细。
6. ✅ 不同账套对应不同审核人；账套之间审核人不可互看、不可代审。
7. ✅ 新增「开票管理员」角色：scope=all，可查看全部账套的申请单、发票与统计，可配置各账套审核人。
8. ✅ 新账号默认 scope=project。
9. ✅ appSecret 加密入库 + 环境变量覆盖 + 支持轮换（旧密钥 24h 回滚窗口）。
10. ✅ 审核人由管理员在界面增删、指定主审人，保存即生效；未分配时按 v0.3 兜底规则（仅 scope=all + 开票审核权限可见）。

**待确认（仅剩以下业务口径）**
1. ⚠️ 单笔金额上限：默认 50,000 元/单，是否按账套调整。
2. ⚠️ 房号格式规则：统一 `楼栋-单元-房号`，还是按项目配置正则。
3. ⚠️ 凭证张数与大小：默认 1–3 张、单张 5MB、合计 12MB 是否合适。
4. ⚠️ 审核与红冲的审批层级：谁审核、红冲是否二级审批。
5. ⚠️ 专票排期：是否在 P1/P2 支持（当前按普票设计）。
6. ⚠️ 历史存量（此前已缴费未开票）是否需要补开入口。
